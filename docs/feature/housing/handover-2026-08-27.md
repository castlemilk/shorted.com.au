### 1. Merge #505 — columnar map delivery — ✅ DONE

### 2. Fix the Census ingest — ✅ PARSER DONE, ingest not yet re-run

`-mode census` ran against prod and left all seven expanded metrics NULL, logging
each miss. **No bad data was written** — the parser resolves columns by header
NAME, so a wrong table degrades to nulls rather than plausible nonsense. That
property is preserved; do not weaken it.

**The mapping in the first draft of this handover was itself partly wrong.**
Re-verified 2026-08-27 by extracting every header line from the real
short-header DataPack (`2021_GCP_SAL_for_AUS_short-header.zip`, 98 MB) rather
than reasoning from table numbers. What shipped:

| Metric | Table | Columns |
|---|---|---|
| Tenure + dwelling count | **G37** | `O_OR_Total`, `O_MTG_Total`, `R_Tot_Total` / `Total_Total` |
| Labour force | **G43** | `lfs_Unmplyed_lookng_for_wrk_P` / `lfs_Tot_LF_P`; `lfs_Tot_LF_P` / `P_15_yrs_over_P` |
| Education | **G43** | `non_sch_qual_{PostGrad_Dgre,Gr_Dip_Gr_Crt,Bchelr_Degree}_P` / `P_15_yrs_over_P` |
| Dwelling structure | **G36** | `OPDs_Separate_house_Dwellings`, `OPDs_Flt_apart_Tot_Dwgs` / `OPDs_Tot_OPDs_Dwellings` |
| Household composition | **G42** | `Tot_FHs_CF_C`, `Tot_Lone_P_H` / `Tot_Tot` |
| Personal income | **G17B + G17C** | `P_1_149_Tot`…`P_400_499_Tot` (G17B), `P_2000_2999_Tot`…`P_3500_more_Tot` (G17C) / `P_Tot_Tot` (G17C) |

Three corrections to the earlier draft, each of which removed work rather than
adding it:

1. **Education is a direct total in G43**, not an age × sex sum from G49A/B. G43
   carries `non_sch_qual_*_P` whole-of-suburb person totals alongside labour
   force. G49A/B is not needed at all.
2. **Personal income needs no summing either.** G17B/G17C carry direct `P_*_Tot`
   band totals — the *original column names in the code were already right*, only
   the table entry (bare `G17`) was wrong.
3. **G26A/B is unpaid child care, not family composition.** The household shares
   come from **G42** ("dwelling structure by household composition") as direct
   household totals.

Net: **no age × sex summing is required for any metric**, which removes the
"a missed column silently understates a share" risk entirely.

The one real complication: the low-income numerators live in G17B while the
denominator `P_Tot_Tot` lives in G17C, so that metric needs a two-file union
keyed on `SAL_CODE_2021` (`combineG17Rows`). A header colliding across the two
files is omitted rather than resolved, so any metric depending on it goes NULL.

Verified against the real DataPack — `TestExpandedCensusRealDataPack`
(skipped unless `CENSUS_DATAPACK_PATH` is set) asserts all 13 fields are
non-NULL for Bondi/Toorak/Ipswich, and the values were independently
recomputed from the raw CSVs and matched to 2dp:

| | Bondi | Toorak | Ipswich |
|---|---|---|---|
| bachelor+ | 51.95% | 51.56% | 16.23% |
| flat/apartment | 79.59% | 49.83% | 15.04% |
| rented | 56.80% | 31.11% | 54.99% |
| unemployment | 4.23% | 3.71% | 11.83% |

Sanity signal worth reusing: outright + mortgage + rented lands on 96.3–96.6%
across all three (the remainder is "other tenure" + "not stated"), which is what
a correct denominator looks like.

### 3. Make a failed ingest fail loudly — ✅ DONE

Eleven modes — `census`, `electorates`, `banners`, `amenities`, `elevation`,
`lga`, `connectivity`, `funding`, `council-financials`, `crime`,
`backfill-address` — now return `error` and dispatch through `ingestExit`, so a
failed ingest exits 1 instead of 0. Guarded by
`TestOperatorIngestModesPropagateFailure` (AST assertion on the dispatch shape).
Full detail in [pipeline.md](pipeline.md#operator-ingest-modes-propagate-failure-2026-08-27).

**One claim in the first draft was overstated.** `-mode census` is not scheduled
in Cloud Run *at all* — `terraform/modules/house-price-collector` schedules only
`-mode all` (monthly) and `-mode drop-index` (daily). So no Cloud Run scheduler
was sitting green on a failing census; it is operator-run, and the exit code
matters for launchd/shell wrappers. The boundary TopoJSON was therefore **not**
shipped into the image: that is 5 MB added to a build context that does not
currently include `web/`, for a mode nothing schedules. `readSuburbRegistry`
already returns a clear per-file error, which now reaches the exit code.

### 4. Process the elevation DEM — ✅ DONE

**LIVE on prod as at 2026-08-27: 15,307 of 15,345 suburbs carry all six
elevation columns.** 9.01 billion DEM cells sampled.

Source, settled: **ELVIS is not required.** The DEM-S national mosaic is a plain
resumable HTTP object on Digital Earth Australia's bucket —
`https://data.dea.ga.gov.au/projects/elevation/ga_srtm_dem1sv1_0/dems1sv1_0.tif`
(38,304,075,388 bytes / 35.7 GiB, `accept-ranges: bytes`). Its siblings
`dem1sv1_0.tif` (DEM) and `demh1sv1_0.tif` (DEM-H) sit beside it under nearly
identical names — the `s` is the product, and `ga_dem_zonal_stats.py` wants DEM-S.
A 20.4 GiB NetCDF of the same product is on NCI THREDDS if space is ever tight:
read `.../DEM-S/catalog.xml` and take `urlPath` — the path needs an `http/`
segment and the file is **not** `dems1sv1_0.nc` but
`Elevation_1secSRTM_DEMs_v1.0_DEM-S_Mosaic_dems1sv1_0.nc`.

Everything lives on the **`gamma-systems-2` external volume** (the internal disk
hit 119 MiB free during this work and cannot hold any of these artifacts):

```
/Volumes/gamma-systems-2/shorted-dem/
  dems1sv1_0.tif            35.7 GiB raster
  venv/                     numpy 2.5.2, rasterio 1.5.1 (GDAL 3.12.4),
                            geopandas 1.1.4, pyproj 3.7.2   (PEP 668 — system
                            python3 is Homebrew-managed and refuses pip install)
  run-zonal.sh              per-state runner, skips completed states
  merge-states.py           merges to one sal_code-keyed artifact; fails closed
  out/<STATE>.json          per-state results + peak RSS in <STATE>.err
```

**Run it per state, not in one pass.** Eight independent runs give progress from
a script that only prints at the end, and isolate failure. Measured peaks:

| state | peak RSS | time | | state | peak RSS | time |
|---|---|---|---|---|---|---|
| ACT | 0.3 GiB | 9 s | | WA | 8.9 GiB | 11m58 |
| NT | 9.7 GiB | 4m24 | | VIC | 2.7 GiB | 1m19 |
| TAS | 2.9 GiB | 14 s | | **QLD** | **16.0 GiB** | 6m51 |
| SA | 9.1 GiB | 3m10 | | NSW | 8.1 GiB | 2m24 |

QLD is the ceiling because Coral Sea's bounding box is 36397×52406 = 1.9e9 cells.
Note peak RSS does **not** scale with the largest polygon — WA holds a bigger
polygon than NT yet peaked lower — because a fixed ~3.2 GiB of it is GDAL's
block cache (`GDAL_CACHEMAX` defaults to 5% of RAM). Cap that first if a machine
is tighter than 64 GB.

**This could not have run before #508.** `summarise_valid_cells` received an
ndarray and did `np.asarray(list(values))`, materialising one Python float object
per cell — ~76 GB for Coral Sea alone — and `_pixel_area_weights` returned a full
raster-sized float64 grid (~15 GB) holding one distinct value per row. Modelled
peak fell from ~114 GB to ~9.5 GB. The pipeline merged in #504 had never been run
against a real DEM, which is why nobody had hit it.

Validated against ground truth, not eyeballed:

- highest max **2224.3 m in Burrungubugge NSW**, next is **Kosciuszko NSW at
  2220.0 m** — Mount Kosciuszko is 2228 m, so a 30 m DEM landing 3.7 m under the
  summit is what correct georeferencing looks like;
- Tasmania tops out at **1567.8 m** against Ben Lomond's 1572 m;
- the **ACT returns `land_share_below_5m` = 0.00% for all 136 suburbs** —
  landlocked and 550 m up. This is the check that exposes a datum or unit error;
- across all 15,307 populated rows: **zero** violations of min ≤ median ≤ max,
  **zero** of below1m ≤ below2m ≤ below5m, **zero** shares outside 0–100.

**Caveat, inherent to the source:** 44 suburbs (0.29%) report a minimum below
−15 m, Australia's lowest natural point. Their medians sit near 70 m, so these
are ordinary inland suburbs carrying a few spurious cells from SRTM void fill.
`elevation_min_m` is a single-cell extremum and noise-sensitive by construction;
the median and area-weighted shares are not. It is an exposed map metric, so a
suburb showing −86 m is the data, not a bug.

DEM-S is **EGM96 orthometric, not AHD**, and nothing here converts vertical datum.

## Upstash hit its command cap — diagnosed and resolved (2026-08-27/28)

The mandatory post-promote sweep (`task deploy:revalidate CONFIRM=prod`) came
back with the ISR paths revalidated but the Redis flush refused:

```
"flushErrors": ["cache:housing:: ERR max requests limit exceeded.
                Limit: 500000, Usage: 500000"]
```

Read that response body carefully, because it is easy to misread twice over.
`revalidated` reflects **only** `flushErrors` — `revalidatePath` runs before the
flush loop, so the ISR pages *were* busted and only the KV layer failed. And the
cap counts **commands, not data**: Upstash's own error links to
`troubleshooting/max_requests_limit`. Flushing the database would not reduce the
number by one, and every `DEL` it took would add to it.

**Attribution, measured rather than guessed.** Two hypotheses were killed:

1. *Prefix flushes are expensive.* `deleteCachedByPrefix` **is** O(total
   keyspace) rather than O(matching keys) — `COUNT` is a work hint and `MATCH`
   filters server-side, so round-trips track total key count. But instrumenting
   it (`flushScanCommands`, #507) measured **1–4 commands per flush**. And
   `pingRevalidate` has three callers against a rig schedule of housing-delta
   daily 10:00, property-resolve daily 21:20, housing-full monthly — a handful
   of flushes a day. Ruled out.
2. *There is a per-request inefficiency.* There is not. `getCached` is a single
   `GET`, `setCached` a single `SETEX`. Nothing to optimise away.

**The tier was simply too small.** 500K/month is ~16,600/day ≈ 11.5/minute; a
suburb page makes several cached reads. The cap was hit *intermittently* — the
sweep succeeded at 20:35 and 21:21 and failed at 17:35 and 21:37 — which is live
consumption crossing the line, not a stale exhaustion that never reset.

**Resolution: the plan was upgraded.** Upstash Pay-as-You-Go is $0.20 per 100K
commands with unlimited commands, the first 1 GB of storage free (the keyspace
is tiny — a flush walks it in one SCAN) and 200 GB/month bandwidth free. At
1–5M commands/month that is **$2–10/month**, and it is the only plan with a
budget cap. Do not re-litigate this: self-hosting a Redis to save single-digit
dollars trades that for a component on the production read path that you own,
size, restart and page for.

A `feat/self-hosted-page-cache` branch exists (Redis + an Upstash-REST-compatible
shim on the VKE cluster, `cache:*` Taskfile tasks, all six resources passing
`kubectl apply --dry-run=server`). It was **deliberately not merged** once the
pricing was known. It is there if the vendor dependency ever needs dropping for
reasons other than cost.

**The consequence that made this urgent**, and the reason not to let a cap sit:
while Upstash rejects writes, the KV last-good layer in `getEconomy.ts` cannot be
populated — so the documented protection against an ISR regen baking a
placeholder for an hour is silently absent exactly when it would be needed. A
degraded cache is not only slower; it removes a guard.

## Operational notes

- **Prod does not run `migrate up`** — hardcoded allowlist, zero housing
  migrations. Apply housing DDL by hand via the **session pooler (5432)** with
  `statement_timeout=0`, **before** merging code that reads the columns, or every
  housing read path 500s. `000113`–`000115` are applied; next free is `000116`.
- **Codex agents have no network**: `buf generate` and `mockgen` are the
  coordinator's job. Widening `ShortsStore` requires regenerating the mock
  (`go generate ./...` in `services/shorts/internal/services/shorts`).
- **Parallel agents trip the pre-push hook**, which lints the whole working tree
  including their half-written files. Verify your own commit's contents before
  bypassing.
- **Stacked PRs auto-close** when the base branch is deleted on merge (#503 was
  lost that way, reopened as #504).
